# 视频创作工作流生成器 (video-workflow-builder) — 设计文档

日期：2026-07-21
状态：待用户评审

## 1. 一句话定位

一个「元技能」(meta-skill)：通过极简访谈 + 联网研究，为用户产出一套**专属的、可直接安装使用的视频创作工作流 skill**，覆盖选题 → 文稿 → 标题 → 封面全流程，目标是让内容适应平台算法（播放量、完播率、播放时长、CTR、互动），帮账号找到目标受众、做出优质内容、被算法青睐。

## 2. 核心设计决策（访谈结论）

| 维度 | 决策 |
|------|------|
| 产出形态 | 生成器 / 元技能：访谈后**生成一个新的专属工作流 skill 文件**（不是运行时自适应） |
| 知识来源 | 内置核心方法论知识库 + 运行时联网补充最新趋势/竞品（C：两者结合） |
| 支持平台 | 抖音、B站、小红书、视频号、百家号 |
| 工作流颗粒度 | 主 skill 编排 + 四个可独立调用的环节模块（选题/文稿/标题/封面） |
| 访谈深度 | **只问 3 件事**：平台、垂类、人设；其余（目标受众、差异化定位、商业化目标）由生成器基于理解 + 联网研究主动分析给出 |
| 定位确认 | 生成工作流的同时附一份诊断说明文档，解释定制理由（C）；且诊断作为独立确认点先给用户过目 |
| 生成完整度 | 完整 skill 目录 + 按垂类需要配套抓取脚本（C） |
| 方法论传承 | 提炼现有资产的通用内核（A）+ 现有 skill 作为质量标杆范例原样打包（C） |
| 算法覆盖深度 | 每平台覆盖四层：推荐机制 / 核心指标与优化点 / 内容形态适配 / 冷启动与破圈 |
| 封面图像生成 | gpt-image-2，走 B站 LLM 网关 `http://llmapi.bilibili.co/v1`（OpenAI SDK 兼容），key 存 `.env` 不硬编码 |

## 4. 生成器工作流程（五阶段，含人工确认点）

### 阶段 0 · 极简访谈（只问 3 件事）
- 主战场平台（可多选：抖音/B站/小红书/视频号/百家号）
- 垂类领域（做什么内容）
- 账号人设（角色/语气/专业背景/价值观）

其余一律不主动追问，靠阶段 1 研究补齐。

### 阶段 1 · 联网研究（生成器做功课）
基于三要素，联网研究：
- 该垂类在该平台的**受众画像**（年龄/身份/痛点/受众心声）
- **当下爆款案例**与共性规律
- **竞品格局**（头部账号在做什么、空白点在哪）
- **变现路径**（该垂类主流商业化方式）
- 平台**最新算法动向**

同时读取内置 `platforms/` 知识库获取该平台推荐机制与指标权重。

### 阶段 2 · 诊断提案（确认点 1）
输出「账号定位诊断 + 策略提案」：
- 目标受众（含受众心声/内心独白）
- 差异化定位（比较优势）
- 内容方向建议
- 变现路径
- 各平台适配建议（若多平台）

**停下来让用户确认 / 微调**，然后才进入生成。

### 阶段 3 · 生成工作流 skill（用户确认定位后）
把「通用方法论内核 × 平台算法逻辑 × 垂类特性 × 诊断结论」融合，定制生成：
- 主 SKILL.md（编排 + 触发词 + 人工决策点）
- 四个环节模块（选题/文稿/标题/封面）
- positioning.md 诊断文档
- 按垂类需要的抓取脚本
- 封面脚本（接 gpt-image-2，key 走 .env）

### 阶段 4 · 交付说明
告知：skill 装在哪、怎么触发、四环节如何单独调用、脚本如何配 key。

## 5. 内置知识库内容标准

### 平台知识库（platforms/*.md）— 统一四层结构
1. **推荐机制**：初始流量池分配、赛马/流量池阶梯、粉丝分发比例、搜索流量占比、社交推荐权重
2. **核心指标与权重**：完播率/CTR/互动率/播放时长/关注转化在该平台各自的权重排序 + 每个指标对应的内容手段
3. **内容形态适配**：最优时长、横竖屏、封面标题规则、图文 vs 视频、发布节奏
4. **冷启动与破圈**：新号起号路径、标签养成、破流量池触发条件、违规红线

平台差异要点（示例）：
- 抖音：重完播 + 强钩子 + 竖屏
- B站：重播放时长 + 长视频可铺垫
- 小红书：重搜索 + 封面标题党 + 图文
- 视频号：重社交裂变推荐
- 百家号：重信息流分发 + 图文权重

### 方法论内核（methodology/*.md）— 跨垂类通用
- `title-craft.md`：提炼 title-gen-v3 核心（好问题/好结论两型、矛盾拉满、靶子要有公共认知、关键词锚定、开头结构呼应）
- `topic-selection.md`：选题通用逻辑（受众动机、比较优势、热点结合、可持续选题库）
- `script-writing.md`：文稿通用逻辑（hook 结构、节奏控制、完播设计、互动引导）
- `cover-design.md`：封面通用逻辑（视觉焦点、文案与标题互补、情绪氛围、平台尺寸适配）

### 范例（exemplars/）
title-gen-v3.md 与 bilibili-finance-video skill 原样打包，作为生成时的质量标杆与结构参照。

## 6. 生成物的四个环节模块（定制逻辑）

每个环节 = 通用方法论 × 该用户平台 × 该垂类 × 诊断结论 融合后的定制版：
- **选题模块**：针对该垂类 + 平台的选题框架（财经=七维度，其它垂类生成对应框架），含联网抓热点指引
- **文稿模块**：该内容形态 + 平台时长的文稿结构
- **标题模块**：title-gen-v3 逻辑 + 该平台标题规则的定制版
- **封面模块**：该平台尺寸 + 封面方法论 + gpt-image-2 生成脚本

主 SKILL.md 编排：全流程串跑（选题→文稿→标题→封面，带人工决策点），也支持单独触发某环节。

## 7. 封面图像生成接入（gpt-image-2）

- 通过 OpenAI SDK 兼容接口，`base_url="http://llmapi.bilibili.co/v1"`
- 模型：`gpt-image-2`（图像生成走 images 接口）
- API key 存 `.env`（`LLM_GATEWAY_API_KEY`），**不硬编码进 SKILL.md 或提交到 git**，`.env` 加入 `.gitignore`，提供 `.env.example`
- 生成脚本按平台尺寸产出（如 B站 4:3、抖音/视频号 竖屏、小红书 3:4）

## 8. 跨工具适配

参照现有 bilibili-finance-video 的做法，生成器与生成物都需说明 Claude Code / Codex 通用：联网搜索、写文件、跑脚本按当前环境映射到等价能力；脚本路径用技能目录绝对路径解析。

## 9. 范围边界（YAGNI）

- 不做运行时自适应执行器（已决定走生成器路线）
- 不支持 YouTube/TikTok/快手等平台（本期仅五个中文平台）
- 访谈不扩展到 3 项之外（受众/差异化/变现由研究补齐）
- 不做数据回流 / 效果追踪闭环（本期只到生成工作流为止）
